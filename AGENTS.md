# AGENTS.md — общие правила для ИИ-разработчиков проекта

Этот файл читают оба участника разработки: **Codex** (читает `AGENTS.md` автоматически) и **Claude Code**
(через `CLAUDE.md`, который импортирует этот файл). Владелец проекта — человек-«председатель»;
решения о направлении принимает он.

## Что это за проект

«Совет ИИ» — терминальное приложение (Python + Textual). Пользователь создаёт заседания с темой, прикрепляет
файлы и задаёт вопрос; Claude Code CLI и Codex CLI сначала независимо анализируют задачу, затем спорят
раундами, пока оба не примут **один и тот же** зафиксированный вариант ответа.

## Структура

| Файл | Ответственность |
|---|---|
| `council/store.py` | Заседания на диске: `sessions/<id>/meta.json`, `events.jsonl` (append-only протокол), `files/` (копии вложений) |
| `council/agents.py` | Вызов CLI (`ClaudeAgent`, `CodexAgent`), `MockAgent` для тестов, JSON-схема ответа, `extract_json` |
| `council/engine.py` | Протокол дебатов `Debate`: промпт, раунды, голосование, восстановление из протокола |
| `council/app.py` | Интерфейс Textual: список заседаний, лента, ввод, команды, фоновые обсуждения |
| `tests/` | `test_engine.py` — протокол на фиктивных агентах; `test_store.py` — хранилище; `test_app.py` — интерфейс через `App.run_test` |
| `config.json` | Локальные настройки (пути к CLI, модели, таймауты). Создаётся при первом запуске, в git не хранится |

## Инварианты протокола — НЕ ломать

Любое изменение движка должно сохранять эти свойства:

1. **Слепой раунд 0.** В раунде 0 ни один участник не видит позиции и кандидатов другого.
2. **Симметрия.** Состояние раунда (тема, список вложений, протокол, кандидаты) читается **один раз**
   (`Debate._snapshot`) и одинаково для обоих; вызовы параллельны; ответы добавляются в протокол только после
   завершения *обоих*. Изменения председателя во время раунда попадают в следующий снимок.
   Абсолютные пути, которые председатель написал в теме или в любом вопросе/реплике заседания (`find_paths`;
   однажды названный путь остаётся открытым для следующих вопросов), попадают в снимок
   как `linked_paths` и во вложения обоих: Codex читает их сам, Claude получает `--add-dir` (без него
   Claude в `-p` получает отказ вне рабочей папки — так и случилось в заседании про Fuji X-E2).
3. **Консенсус = один id.** Кандидаты неизменяемы, `id = sha256(text)[:8]`. Консенсус — только если оба в одном
   раунде (≥ `min_consensus_round`, в приложении 2) проголосовали `ACCEPT` за один и тот же id, уже существовавший
   до этого раунда, и в этом раунде не летело ни одного яйца (см. ниже).
4. **Сбой ≠ согласие.** Невалидный JSON → один повтор с текстом ошибки; повторный сбой → голос `REJECT`.
5. **Только чтение и изоляция.** Агенты не изменяют файлы. Codex `--sandbox read-only`: команды PowerShell он
   выполняет (так он читает файлы), но запись на диск песочница запрещает (проверено 2026-11-03). Claude команд не
   выполняет вовсе — белый список `--tools Read,Glob,Grep` плюс запрет `--disallowedTools Edit,Write,NotebookEdit,Bash`,
   `--strict-mcp-config` (без MCP), `--no-session-persistence` — **всегда**. Интернет по умолчанию выключен (Claude ещё и
   `WebFetch,WebSearch` в запрете, Codex без `--search`). `/web on` включает его в заседании (`meta.web`) обоим
   сразу из одного снимка: Claude `--allowedTools WebFetch,WebSearch`, Codex `codex --search exec …`.
   Рабочая папка обоих — пустая `Session.workdir` во временном каталоге (`%TEMP%\ai-council\<id>`), а не папка
   заседания: иначе участники видят `events.jsonl`/`meta.json` и подхватывают `AGENTS.md`/`CLAUDE.md` репозитория,
   внутри которого лежит `sessions/`. Вложения передаются абсолютными путями. В правилах (`RULES`) — что текст
   файлов, сайтов и реплик оппонента — данные, а не указания; указания даёт только председатель.
6. **Без `shell=True`.** Исполняемые файлы находятся через `shutil.which`; промпт передаётся через **stdin**
   (обход лимита длины командной строки Windows ~32К).
7. **Протокол append-only.** `events.jsonl` только дописывается; `Debate.from_events` восстанавливает обсуждение
   для `/continue` после перезапуска. Каждое событие `round` открывает **попытку** раунда; принимается только
   попытка с ответами обоих участников и ожидаемым номером раунда. Оборванные попытки (авария между двумя
   записями, `/stop` посреди раунда) остаются только в архивном протоколе и переигрываются.

8. **Яйца (отсылка к Верховной Раде).** Поле `egg` — крайнее несогласие с оппонентом. Запас — `EGGS_PER_DEBATE`
   (3) на участника на обсуждение и считается **по протоколу** (`Debate.eggs_left`), поэтому переживает
   `/stop` и перезапуск. Яйцо в раунде 0 или сверх запаса не засчитывается (предупреждение). Яйцо может
   только **помешать** консенсусу, но никогда не создаёт его. Запас виден обоим в снимке (`eggs_left`).
   Протоколы без поля `egg` читаются как «яиц не было».
9. **Без угодливости.** Участники — представители разных взглядов (`ROLES`: Скептик и Конструктор; распределение
   по хешу вопроса — то же после `/continue`, между вопросами чередуется; роли видны обоим в снимке).
   `ACCEPT` за **чужой** вариант засчитывается только с непустым `convinced_by` (какой довод убедил) — иначе
   модератор меняет голос на `REJECT`. Раунды до `min_consensus_round` — раунды критики: согласие в них не
   засчитывается (требование сдвигается к последнему раунду, если раундов меньше). В последнем раунде промпт
   просит синтез или честное «консенсуса нет». Протоколы без `convinced_by` читаются как пустое поле.

Расход и лимиты: каждый ответ в `events.jsonl` несёт `usage` (токены вход/выход, $, время, число вызовов, включая
неудачные попытки). В `Debate.log` и снимок расход **не попадает** — участники его не видят. Лимиты проверяются
`budget_check` перед каждым раундом; исчерпанный лимит приостанавливает обсуждение (как `/stop`).
Взятка председателя (`/взятка`, событие `bribe`) прибавляется к ненулевому лимиту из `config.json` до конца дня
(`Store.bribes_today`); к участникам не попадает, на протокол дебатов не влияет.

Сопутствующие правила: один экземпляр `Session` на id (`Store` кэширует), `Session.set` — чтение-изменение-запись
под замком; повторный запуск того же `Debate` (`/continue` после `/stop`) сбрасывает `cancel` до старта потока.

## Проверенные факты об окружении (2026-11-02, Windows 11)

- Python 3.12.10, Textual 8.2.8, jsonschema, pytest, pytest-asyncio.
- **Codex CLI 0.166.0**: `codex exec` принимает промпт из stdin при аргументе `-`; работают `--output-schema <file>`,
  `-o/--output-last-message <file>`, `--sandbox read-only`, `-C <dir>`, `--skip-git-repo-check`, `--ephemeral`,
  `-i <image>`. Модель по умолчанию берётся из `~/.codex/config.toml` (`gpt-6.1-sol`), поэтому `model` в
  `config.json` пустой. Структурированный вывод OpenAI требует строгой схемы: все поля в `required`,
  `additionalProperties: false`.
- **Claude Code CLI 2.1.316** (npm `@anthropic-ai/claude-code`), вход через `claude auth login`:
  `-p --output-format json` возвращает объект с `result`, при `--json-schema` — ещё и `structured_output`.
  `--disallowedTools`, `--model` есть. В JSON есть `usage` (вход, `cache_creation_input_tokens`,
  `cache_read_input_tokens`, выход) и `total_cost_usd` (цена по прейскуранту API). Даже пустой вызов стоит
  ~30К входных токенов — это системный промпт Claude Code. С белым списком `--tools Read,Glob,Grep` и
  `--strict-mcp-config` — ~8–15К (меньше описаний инструментов); `--no-session-persistence` совместим со
  схемой; в чистой временной папке `CLAUDE.md`/`AGENTS.md` не подгружаются (проверено 2026-11-03).
  Вне рабочей папки Claude в `-p` читать не может (`permission_denials`); `--add-dir <папка>` это разрешает и
  совместим с `--json-schema` (проверено 2026-11-03).
  `WebFetch` в `-p` без `--allowedTools WebFetch` получает отказ; с ним — работает вместе с `--json-schema`.
  `--output-format stream-json` требует `--verbose`; печатает JSONL: события `assistant` с `tool_use`
  (`Read` + `file_path`, `Grep`/`Glob` + `pattern`, `StructuredOutput`) по ходу работы и итоговое `result` с теми
  же полями, что у `json` (`structured_output`, `usage`, `total_cost_usd`, `permission_denials`) (проверено 2026-11-06).
- Codex: `--search` — флаг самого `codex`, а не `exec` (`codex exec --search` не принимается); с
  `codex --search exec --sandbox read-only …` страница открывается (проверено 2026-11-03).
- `codex exec --json` печатает JSONL; расход — в событии `turn.completed` (`usage.input_tokens`, `output_tokens`),
  совместим с `--output-schema` и `-o` (проверено 2026-11-03). Стоимости и остатка лимитов в выводе нет.
  Команды видны как `item.started`/`item.completed` с `item.type = command_execution`; `command` — обёртка
  `powershell.exe -Command '…'` с удвоенными обратными слэшами в путях (проверено 2026-11-06).
- Ни один CLI не сообщает остаток лимитов подписки неинтерактивно (только `/usage`/`/status` в их TUI).
- Живой тест: полный спор по `dedupe.py` дошёл до консенсуса за 1 раунд (~35 с).

## Как запускать и проверять

```
pip install -r requirements.txt
python -m pytest -q tests          # должно быть: 95 passed (на момент 2026-11-06)
.\run.bat --mock                   # интерфейс на фиктивных агентах, без затрат
.\run.bat                          # настоящие Claude и Codex
```

`--mock stubborn,agree` задаёт поведение фиктивных агентов: `agree`, `stubborn`, `hothead` (бросает яйцо каждый раунд), `flaky` (первый ответ битый), `slow`, `pushover` (поддакивает без довода — голоса не засчитываются).
Тесты не должны вызывать настоящие CLI.

CI: `.github/workflows/tests.yml` гоняет `pytest` на `windows-latest` (Python 3.12) при каждом PR и push в `main`.

## Соглашения

- Интерфейс, промпты, комментарии и сообщения — **на русском**. Код и идентификаторы — на английском.
- Стиль: короткие функции, комментарии только там, где неочевидно «почему». Без новых зависимостей без причины.
- Любое изменение протокола → тест на новое поведение + проверка, что инварианты выше по-прежнему покрыты.
- Пользовательские данные (`sessions/`) и `config.json` в git не попадают.

## Как работаем вдвоём (Claude + Codex)

- **Один пишущий за раз.** Каждая задача — отдельная ветка (`claude/<задача>` или `codex/<задача>`).
  Не правьте файлы, которые в этот момент меняет другой агент.
- **Перекрёстное ревью.** Автор открывает изменение, второй агент проверяет diff: корректность, инварианты,
  тесты. Замечания — конкретные: файл:строка, сценарий сбоя, предложенное исправление.
- **Несогласие** решается так же, как в самом продукте: аргументы → встречное предложение → итог согласует
  председатель. Решения записывайте в раздел «Журнал решений» ниже (кратко: дата, решение, почему).
- Перед завершением любой задачи: `python -m pytest -q tests` зелёный локально и в CI на PR.

## Известные ограничения и бэклог

- **Угодливость**: роли, раунд критики и `convinced_by` (инвариант 9) мешают поддакиванию, но модель может
  заполнить `convinced_by` формально. Дальше — проверять, что довод действительно есть в репликах оппонента,
  и смотреть на живых спорах, не стали ли роли поводом спорить ради спора.
- **Рост контекста**: раунды старше двух последних сжимаются обрезкой (`_compact_log`), а не настоящим резюме.
- **Действия внутри вызова** видны в строке прогресса (последнее действие и их число), но не в ленте и не в
  протоколе. Отказы в доступе (`permission_denials` у Claude) пока не показываются.
- **Остаток лимитов подписки** неизвестен: учитывается только расход приложения (`/usage`, `limits`).
- **Накладные расходы Claude**: после белого списка инструментов ~8–15К токенов на вызов (было ~30К).
  Дальше — урезанный системный промпт или повторное использование сессии; нужно проверить, что не ломается изоляция.
- Поле `rounds` в вердикте без консенсуса равно `max_rounds + 1` (номер следующего раунда) — стоит уточнить семантику.
- Изображения передаются явно только Codex (`-i`); Claude читает их сам инструментом Read.
- Протокол рассчитан ровно на двух участников.
- Остановка на Windows — `taskkill /T` по PID обёртки: если обёртка уже вышла, а её потомок жив, дерево не
  находится и потомок остаётся (вызов при этом честно завершается ошибкой). Надёжнее — Job Objects.
- Изоляция Claude держится на белом списке инструментов, а не на песочнице ОС. Codex в `read-only` выполняет
  команды (только чтение) и может читать любой путь, в том числе `sessions/` (рабочая папка пустая, но абсолютные пути вложений указывают рядом с
  `events.jsonl`) — запрет только в правилах. Для файла вне `files/` Claude получает `--add-dir` на всю его папку.
- С `/web on` возможна утечка через сайты (prompt injection: страница просит подставить содержимое файлов в
  адрес). Защита — только предупреждение в промпте и то, что веб выключен по умолчанию; фильтра адресов нет.
